# MANDO UI/UX DESIGN SKILL

## 1. Core Principle

Design must communicate functionality without instructions.

* Every interactive element must look interactive
* Every state must be visually distinguishable
* Every action must produce feedback

---

## 2. Visual Hierarchy

Prioritize content using size, position, and contrast.

Rules:

* Most important elements → larger, higher, higher contrast
* Secondary information → smaller, lower emphasis

Application:

* Title > Price > Metadata
* Images improve scanability and should be used when possible

---

## 3. Component Structure (Cards)

Use consistent, repeatable layouts.

Standard structure:

* Image (optional but preferred)
* Primary text (title)
* Secondary text (details)
* Metadata (small text)
* Actions (buttons/icons)

---

## 4. Spacing System

Use a consistent spacing scale.

Rules:

* Use multiples of 4 or 8
* 32px → section spacing
* 16px → related blocks
* 8px → text grouping

Principle:

* Related elements → closer
* Unrelated elements → more space

---

## 5. Typography

Keep typography simple and controlled.

Rules:

* Use one font family (sans-serif recommended)
* Limit to 5–6 font sizes

Guidelines:

* Large text: tighter letter spacing (-2% to -3%)
* Line height: 110%–130%

---

## 6. Color System

Use color with purpose, not decoration.

Structure:

* Primary color (brand)
* Variants (lighter/darker)

Semantic colors:

* Blue → action / trust
* Green → success
* Red → error
* Yellow → warning

---

## 7. Component States (Mandatory)

### Buttons:

* Default
* Hover
* Active (pressed)
* Disabled
* Loading (optional but recommended)

### Inputs:

* Default
* Focus
* Error (with message)
* Success (optional)

Principle:
Every interaction must provide visual feedback.

---

## 8. Icons

Use icons to support meaning, not replace clarity.

Rules:

* Icon size ≈ text line height (20–24px)
* Avoid oversized icons
* Use for quick recognition (location, time, actions)

---

## 9. White Space

White space is critical for readability and clarity.

Rules:

* Avoid clutter
* Separate sections clearly
* Allow content to “breathe”

---

## 10. Feedback & Microinteractions

Every user action must trigger a response.

Examples:

* Save → confirmation message
* Copy → “Copied” feedback
* Loading → spinner
* Errors → visible messages

Microinteractions:

* Enhance feedback (animations, transitions)
* Improve perceived quality and trust

---

## 11. Depth & Shadows

### Light Mode:

* Use soft shadows
* Low opacity, high blur

Rule:
Shadows should not draw attention.

---

## 12. Dark Mode (if applicable)

Do not invert colors directly.

Rules:

* Avoid pure black backgrounds
* Use lighter surfaces over darker backgrounds
* Reduce color saturation

---

## 13. Buttons & CTAs

Types:

* Primary → main action
* Secondary → alternative (ghost button)

Rules:

* Horizontal padding ≈ 2× vertical padding
* Clear visual distinction between types

---

## 14. Overlays (Text over Images)

Problem:
Text readability over images

Solutions:

* Gradient overlays
* Progressive blur

---

## 15. Consistency

Maintain consistent patterns across the entire system.

Rules:

* Same components → same behavior
* Same actions → same visual style

---

## 16. Design Validation Checklist

Before shipping any UI:

* Is it understandable without instructions?
* Does hierarchy clearly guide attention?
* Is spacing consistent and readable?
* Are all states defined?
* Does every action provide feedback?
* Is color used meaningfully?
* Is the design consistent with the system?

---

## 17. Product-Oriented Principle

Target users are non-technical.

Therefore, design must be:

* Intuitive
* Self-explanatory
* Low-friction

Outcome:

* Reduced onboarding time
* Increased activation
* Lower support dependency
